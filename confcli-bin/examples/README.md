# Примеры профилей экспорта и импорта

Эти профили демонстрируют возможности confcli 0.0.16. Основная [инструкция по эксплуатации](../../README.md) описывает команды, настройки и ограничения; [CHANGELOG](../../CHANGELOG.md) содержит историю изменений инструмента.

- [export-preserve-macros.yaml](export-preserve-macros.yaml): экспорт целых страниц со структурой макросов, видимыми Include/Excerpt Include и метаданными.
- [import-preserve-macros.yaml](import-preserve-macros.yaml): восстановление макросов, локальные вложения, ссылочный PlantUML и ссылки на файлы TFS.

## Подготовка

Замените пространство, корневые ID, URL репозитория, `repository-id` и опубликованную ветку на значения своей среды. Добавьте исключения экспорта и импорта при необходимости. Для существующих страниц настройте `overrides.page_id` и `overrides.title` отдельно для тестового и рабочего пространств. Полный набор исходных файлов должен оставаться доступным при поштучном импорте.

Маски вложений и пути `overrides` считаются от `--from`. В примере маски `_attachments/**` и `_diagrams/**` рассчитаны на корень экспортированного дерева. При `--from docs` для файлов в `docs/requirements` нужны маски `requirements/_attachments/**` и `requirements/_diagrams/**`. Выбираются только связанные со страницей файлы; не добавляйте архивы Markdown широкими масками.

## Экспорт

```powershell
confcli --read-only hierarchy space --space SOURCE --page-id 12345 --transform ./confcli-bin/examples/export-preserve-macros.yaml --output-dir ./export --skip-root
```

Проверьте итог `success / failed / skipped`. Вложенные страницы должны быть целыми документами; Include не создаёт отдельного документа-фрагмента. Изображения и вложения остаются по исходным ссылкам: скачивание двоичных файлов и замена ссылок на локальные являются отдельным этапом. После изменения запечатанного снимка Include нужна пересчитанная контрольная сумма; готового CLI-флага для этого нет.

## Импорт выбранной страницы

```powershell
confcli --read-only --format json sync --profile ./confcli-bin/examples/import-preserve-macros.yaml --from ./export --space TEST --root 67890 --file 'Раздел/Документ.md' --dry-run
```

Проверьте ID, заголовок, родителя, вложения и ошибки. Существующие родители остаются `skip`; отсутствующего родителя необходимо создать отдельно. Перед применением заново сравните актуальную страницу и исходные файлы. Для записи выполните ту же команду без `--read-only` и `--dry-run` в конфигурации с `read_only: false`; флага `--apply` нет.

Проверьте отображение результата и повторите dry-run: неизменённая страница должна быть пропущена, без загрузки вложений. После приёмки в тестовом пространстве используйте отдельное сопоставление ID для рабочего пространства.

`sync` заменяет body целиком и создаёт следующую версию при обновлении. Автоматического слияния редакций и защиты от изменений после предыдущего dry-run нет. `update` по хешу не означает содержательного отличия. Orphan только перечисляются; предварительное удаление существующих страниц не требуется. Загрузка страницы и вложений не является одной транзакцией.

PNG и `.drawio` импортируются как изображение и ссылка на исходник. Ссылочный PlantUML зависит от доступности файла в опубликованной ветке; локальная ветка недоступна плагину Confluence. Стили диаграмм и предупреждения PlantUML автоматически не исправляются.
